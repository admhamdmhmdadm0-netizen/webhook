# نشر UNIXSMS Webhook Bridge على Orkestr

تستخدم Orkestr النشر من مستودع GitHub أو GitLab أو Bitbucket أو Codeberg. لذلك ارفع ملفات هذا المشروع إلى مستودع جديد، أو استخدم مستودعًا خاصًا بعد ربط مزود Git من إعدادات Orkestr.

## ملفات المستودع

ضع هذه الملفات في جذر المستودع:

```text
Dockerfile
requirements.txt
webhook_bridge.py
```

يوجد Dockerfile جاهز يشغل التطبيق بالأمر:

```text
python webhook_bridge.py
```

والتطبيق يستمع على `0.0.0.0` والمنفذ الموجود في متغير `PORT`.

## إنشاء المشروع

من لوحة Orkestr افتح **Projects** ثم **New Project**، واختر مستودع Git الذي رفعت إليه الملفات، ثم اختر الفرع `main`. إذا ظهر اختيار الخدمة، اختر جذر المستودع. سيكتشف Orkestr ملف Dockerfile ويستخدمه.

## متغيرات البيئة

افتح المشروع، ثم بيئة `production`، ثم قسم **Environment Variables**، وأضف المتغيرات التالية. لا ترفع ملف `.env` إلى Git:

```text
WEBHOOK_PATH_TOKEN=ضع_سرًا_طويلًا_جديدًا
BOT_READ_TOKEN=نفس_توكن_البوت
PORT=8000
MAX_CDR_RECORDS=200
MEMORY_LIMIT=50000
LOG_LEVEL=INFO
```

إذا كانت Orkestr تعرض منفذًا مختلفًا أو إعدادًا خاصًا بالمنفذ، استخدم منفذ البيئة `PORT` نفسه. لا تستخدم `127.0.0.1` في التطبيق؛ الكود يستمع على `0.0.0.0` حتى تصل إليه شبكة Orkestr.

بعد حفظ المتغيرات اضغط **Deploy** أو **Save & redeploy**؛ تغيير المتغيرات لا يؤثر على الحاوية الحالية قبل إعادة النشر.

## الرابط العام

عند نجاح النشر وحالة **Live**، تعطي Orkestr رابطًا مثل:

```text
https://اسم-المشروع.orkestr.run
```

اختبر:

```text
https://اسم-المشروع.orkestr.run/health
```

ويجب أن يظهر JSON يحتوي على `ok: true`.

## ربط UNIXSMS

في صفحة UNIXSMS Webhook ضع:

```text
https://اسم-المشروع.orkestr.run/webhook/قيمة_WEBHOOK_PATH_TOKEN
```

فعّل التسليم ثم أرسل اختبارًا. لا تضع `/webhook` وحدها؛ يجب أن تكون قيمة السر في نهاية المسار.

## ربط البوت

في إعداد لوحة البوت ضع:

```text
https://اسم-المشروع.orkestr.run/v2/cdr
```

واستخدم المصادقة `Query`، واسم المعامل `token`، وقيمة `BOT_READ_TOKEN` نفسها.

إذا استخدمت نسخة Long Polling المعدلة، اجعل مزود اللوحة `unixsms_webhook_bridge`، وليس `unixsms`، حتى لا يفرض البوت فاصل طلبات UNIXSMS القديم. استخدم ملف إعداد اللوحة الموجود في حزمة التحديث السابقة.

## تنبيهات التشغيل

في الخطة المجانية قد تدخل التطبيقات غير النشطة في وضع النوم، وقد يكون أول طلب بعد النوم أبطأ. كذلك نظام الجسر الحالي يحفظ الرسائل في الذاكرة، لذلك تضيع الرسائل الموجودة عند إعادة تشغيل الحاوية أو إعادة النشر. هذا مناسب للاختبار والتسليم السريع، أما التشغيل الموثوق فيحتاج قاعدة بيانات أو Redis دائمًا.

لا تضع أي API key أو password أو `.env` في مستودع Git. أنشئ متغيرات البيئة من لوحة Orkestr، فهي مشفرة ومحقونة وقت التشغيل.
